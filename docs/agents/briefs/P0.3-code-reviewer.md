## Review checklist for P0.3

**Scope and process**

1. P0.3 commits touch only P0.3's paths in the ownership table, one block appended at the end of the root `CMakeLists.txt` (`# ---- P0.3: … ----` / `# ---- end P0.3 ----`, nothing else changed), one added row in the docs/dev/build.md dependency table, and only the `execution` blocks of the three hidden test presets in `CMakePresets.json`. Messages start `P0.3: `.
2. `ctest --preset linux-debug` in a build directory with tests fails if no tests are registered (carried follow-up): check the preset JSON and run `ctest --preset linux-debug -R nonexistent-name` (expect a non-zero exit with "No tests were found").

**R1**

3. `pme_add_doctest` registers one CTest test per `TEST_CASE`, requires `LABELS`, sets warnings as errors; `ctest -N -L unit` lists P0.3's test cases by their names.
4. `test_p0_3_r1_test_names_carry_ids` passes on the branch; in scratch, add a `TEST_CASE("bad name")` and a Python `test_bad` — it must fail naming both.
5. docs/dev/testing.md documents names, labels, `pme_add_doctest`, running one test, and oracle-registry updates.

**R2**

6. `engine/tests/oracles.md` has 19 rows in SPEC-ORC order; setup, expected value and tolerance match SPEC-ORC verbatim (diff them); owning phases and gates match the brief's table; ORC-16 reads "unassigned (G2)"; every status is `not implemented`.

**R3 and T1**

7. C++ and Python T1 tests exist under the names `P0.3-T1 …` and `test_p0_3_t1_…`, use the brief's three cases from the shared JSON, and pass with the card's tolerances (0.01 cent, 0.5%). Record the worst errors.
8. Independent check (write it as a committed test if it passes, or as a finding if it fails): a signal the implementer did not use — for example 12 partials of f₀ = 110 Hz, B = 10⁻⁴, σ_n = 0.2 + 2 × 10⁻⁶ f_n², 48 kHz, 3 s, plus a partial pair 1.2 Hz apart near 440 Hz — through both C++ and Python. Same tolerances.
9. C++ and Python agree with each other on Case B within the T1 tolerances.
10. B fit, double-decay fit, contact time (sub-sample), spectral envelope and energy-drift tests exist with `P0.3-R3` names and pass. The FFT and solver have tests against direct implementations. No third-party dependency other than nlohmann/json was added.

**R4 and T2**

11. `golden-features.schema.json` is valid draft 2020-12, has `schema_version`, units, and per-feature tolerances with the documented defaults. T2 cases (identical passes; +1% σ fails naming the partial; +0.4% passes) pass in C++ and Python; `pme_golden_compare` exit codes are 0/1.
12. nlohmann/json pin: `git ls-remote https://github.com/nlohmann/json 'refs/tags/<tag>^{}'` prints exactly the pinned SHA; the tag is the latest release; the build.md row and the `dependencies.cmake` comment block (URL, tag, SPDX `MIT`, purpose, first phase) exist.

**R5**

13. WAV round-trip tests for 16/24/32-bit integer and 32/64-bit float, multichannel, pass; a WAV written by C++ reads identically in Python (`scipy.io.wavfile` or the mirror) and vice versa — run it.
14. In scratch, link `pme_analysis` into `pme_osc`: configure must fail with the link-check message. Without it, `pme_engine`'s link closure contains none of `pme_analysis`, `pme_test_framework`, `pme_bench`, `nlohmann_json`.

**R6 and T3**

15. `compare.py` uses the strict 5% rule; T3 cases (+10% fails, +4% passes, −10% passes) pass; benchmarks present in one file only are reported, not failed. The smoke benchmark runs under `ctest -L perf` and writes JSON that the comparator accepts.

**Quality**

16. `clang-format --dry-run --Werror` and `clang-tidy -p build/linux-debug` pass on all P0.3 C++; `ruff check`, `ruff format --check`, `mypy` (strict) and `check_spdx.py` pass. All P0.3 tests pass in `linux-debug` and `linux-rt-safety` with GCC and Clang.
