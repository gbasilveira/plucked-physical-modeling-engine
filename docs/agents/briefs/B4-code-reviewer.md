- **B4-T3** an imported MAESSTRO sample yields a valid blob.

## Review checklist for B4

**Scope and process**

1. B4 commits touch only the B4 rows of the ownership table and, if any, one dependency line plus a regenerated (not hand-merged) `uv.lock` in its own commit. No change to `compiler/pme_compiler/body/` or `schema/`. Messages start `B4: `.

**Physics and conventions**

2. The mobility model is Y\_ab = Σ iω Φ\_k(a)Φ\_k(b)/(Ω\_k² − ω² + 2iσ\_kω) under e^(+iωt); pole-to-mode conversion Ω\_k = √(ω\_d² + σ²) correct; Φ signs from transfer residues. Check one case by hand.
3. Membrane formulas and normalisation constants correct (verify N\_mn yourself by quadrature for m = 0, 1, 3); the degenerate cos/sin pair included; frame and sampling at bridge points documented.
4. Helmholtz frequency formula, end correction and c₀ cited; the mode is merged sorted; its coupling Φ comes from the caller, as briefed.
5. CSV: columns, units and the three damping forms as briefed; every rejection names row and column; outputs sorted.

**Data and provenance**

6. The MAESSTRO format is cited from public material; no third-party code or data copied; the fixture is synthetic, generated by a committed script, labelled, MIT. If B4-R1 is `partial`, the report says exactly what sample is needed.
7. Vector fitting is our implementation and cites Gustavsen and Semlyen (1999).

**Output and tests**

8. Every route produces a table that passes `modal_blob.validate`, writes through `modal_blob.write`/`attach` with the right `source` (`ModalTable` or `MeasuredMobilityFit`), and loads with `load(verify_blobs=True)`.
9. B4-T1 includes close modes and noise, matches modes to the truth, and applies 0.5% and 5% per mode; B4-T2 checks Bessel zeros two independent ways at 10⁻⁹ and normalisation; B4-T3 as briefed.
10. `uv run ruff check`, `ruff format --check`, `mypy` (strict) clean; `test_p0_3_r1` passes; runtimes acceptable.
11. docs/dev/body-import.md names SPEC-BODY and documents each route as briefed.
