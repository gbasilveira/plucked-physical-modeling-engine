### Rib model (the convention B2-T4 compares against)

A rib `RibDesc` is an Euler–Bernoulli beam along its axis, attached to the plate's mid-surface (z = 0, SPEC-BODY "Body frame"):

- bending stiffness E I = `youngs` · `width` · `height`³ / 12 (out-of-plane bending, `height` normal to the plate); mass per length ρA = `density` · `width` · `height`;
- energy added to the plate: ½ ∫ E I (∂²w/∂s²)² ds (s along the axis) and ½ ∫ ρA (∂w/∂t)² ds;
- neglected, and stated in docs/dev/reference-solver.md and reference/README.md: torsional stiffness, rotary inertia, the offset between beam and plate mid-surfaces, and moisture dependence of rib properties.

### Discretisation

- **Axis-parallel only.** A rib must be parallel to x or to y (|Δy| or |Δx| at most 10⁻⁹ m), have z = 0 at both ends, positive width, height, youngs and density, and lie inside the rectangle; otherwise `RefError` naming `ribs[i]` and the field. Diagonal ribs stay rejected ("ribs[i]: only axis-parallel ribs are modelled").
- **On grid lines.** On the chosen grid (nx, ny), the rib's line and both end points must fall on grid nodes within 10⁻⁹ · h; otherwise `RefError` naming `ribs[i]` and the grid (callers pick grids that contain the rib lines, for example nx a multiple of 4 for ribs at x = Lx/4, Lx/2, 3Lx/4). Rib ends on the plate edge or inside the plate are both allowed.
- **Stiffness:** K\_rib = Σ over the rib's interior line nodes p of E I · h\_s · (δ\_ss w)\_p², δ\_ss the 3-point second difference along the line with spacing h\_s (hx or hy), with w = 0 at simply supported plate-edge nodes. Assemble into the plate's banded K (the existing half-bandwidth suffices for a line stencil; check). K\_rib is symmetric positive semi-definite.
- **Mass:** lumped, ρA · h\_s per line node, ρA · h\_s / 2 at the rib's two end nodes (trapezoid), added to the plate's nodal mass. The plate's mass changes from one scalar per node to a vector (`PlateOperator`); keep the scalar path bit-identical when there are no ribs.
- Crossing ribs simply add. Ribs leave the energy identity of docs/dev/reference-solver.md unchanged in form (they are part of M and K), so the coupled simulation with strings stays exactly energy-conserving.
- Remove the `ribs` rejection from `derive_plate` and the `maxItems: 0` from `scenario.schema.json` (`ribs` now an array of `{start, end, width, height, youngs, density}`); every other plate limit stays rejected exactly as now.

### Modal solve (new)

`plate_modes(const PlateConstants&, const std::vector<RibDesc>&, int nx, int ny, int count, …)` returns the `count` lowest eigenpairs of K φ = ω² M φ of the discrete operator (frequencies in Hz ascending, and, on request, mode values at given points by the existing bilinear interpolation, mass-normalised with the discrete M):

- symmetric form A = M^(−1/2) K M^(−1/2) (M diagonal positive), banded;
- **block inverse (subspace) iteration with Rayleigh–Ritz**: factor A once with the reference's `BandCholesky`; block size p = count + max(10, count/2); a fixed, documented starting block (deterministic, for example a fixed-seed generator); M- or A-orthonormalise the block each iteration; the projected p × p problem solved by a **cyclic Jacobi** eigen-solver written in the reference; stop when every one of the `count` lowest Ritz values changes by less than 10⁻¹³ relative between iterations, or fail with `RefError` after a documented maximum (for example 500);
- a residual check on return: ‖Kφ − ω²Mφ‖ / (ω² ‖Mφ‖) ≤ 10⁻⁹ for each returned pair, else `RefError`.

Expose it as `pme_reference.plate_modes(plate: dict, nx: int, ny: int, count: int, points: list | None = None) -> dict` (frequencies, and values at the points when given) using the same `plate` JSON as scenarios, and as a CLI subcommand `pme_reference_cli plate-modes <scenario.json> --count N` that prints JSON. Simulation scenarios with ribs run through the existing time stepper (ribs are part of K and M).
