### How to meet each requirement

- Files: `engine/include/pme/<name>.hpp` for the thirteen names of R2, plus at most three shared headers: `status.hpp` (`Status`, `toString`, ADR-0006), `types.hpp` (small vocabulary types several modules share, such as `Point`), `version.hpp` (`inline constexpr int interfacesVersionMajor = 1;` and the compatibility statement of R6). An umbrella `pme.hpp` that includes the others is allowed. Namespace `pme`.
- Placement (every name SPEC-API declares must appear exactly once):

  | Header | Declares |
  | --- | --- |
  | osc.hpp | `OscCoeffs`, `compileOscillator` |
  | string.hpp | `StringParams`, `Boundary`, `BridgeEnd`, `StringModes`, `compileString` |
  | bridge.hpp | `SegmentBridgeTerms`, `compileBridgeTerms`, `BridgePointDesc` |
  | body.hpp | `BodyParams`, `BodySource`, `BodyModes`, `LocalBridge`, `ChannelDesc`, `compileBody`, `buildLocalBridge` |
  | nonlinear.hpp | public types SPEC-NL needs in descriptions, if any; otherwise a documented header stating that interfaces-v1 declares no nonlinear API |
  | exciters.hpp | `HammerParams`, `FeltLaw`, `UnaCordaParams`, `PluckPulse`, `Plectrum`, `Finger`, `ExciterParams` |
  | dampers.hpp | `DamperParams`, `DamperMode` |

- Fields: exactly SPEC-API's fields, names and types, in SPEC's order, with SI units in the documentation of each field (SPEC-CONV). Default member initialisers where SPEC-INST's piano defaults give a value; otherwise value-initialised.
- Types SPEC-API names without listing members (`OscCoeffs`, `StringModes`, `SegmentBridgeTerms`, `BodyModes`, `LocalBridge`, `PluckPulse`, `Plectrum`, `Finger`, `BridgePointDesc`, `ChannelDesc`, `TuningCurve`, `Defaults`, `BodyParams`' plate/table members, `Point`, `AudioOut`, `Diagnostic`): take members from the SPEC section that defines the quantities and cite it per member (for example `OscCoeffs` from SPEC-OSC's Contract). **Do not invent physics.** Where SPEC defines no members at all, declare the type with the minimum members its consumers in SPEC-API and SPEC-EXEC need, mark it **provisional** in its documentation and in docs/dev/interfaces.md, and list it in the report's `spec_issues` as a described gap for the planner to file. Compiled-data types must be readable by tests through the public header (oracle tests are written from public headers only).
- Signatures: ADR-0006 exactly. Non-real-time functions that can fail return `[[nodiscard]] Status` with the SPEC return type as a final reference out-parameter; `Engine::prepare` returns `[[nodiscard]] Status`; `setInstrument`, `process`, `reset`, `popDiagnostic` keep SPEC's signatures and are `noexcept`. `Engine` holds its state behind a private pointer to an incomplete `Impl` (headers stay declarations only; the `Impl` is allocated in `prepare` or the constructor, never in `process`). Copy deleted; move allowed.
- Documentation: every declaration has a comment naming its SPEC key and, for each function, its thread (non-audio, any, audio only — from SPEC-API), whether it may allocate, and its failure statuses. Public headers contain declarations and documentation only: no function bodies other than `= default` / `= delete`; `constexpr` constants and enum definitions are allowed.
- Standard library only in public headers (`<cstdint>`, `<memory>`, `<optional>`, `<span>`, `<string>`, `<string_view>`, `<variant>`, `<vector>` …); no Highway, no doctest, no platform headers.

- Every non-real-time stub returns `Status::NotImplemented` and leaves its out-parameter unchanged — except argument checks the SPEC states explicitly, which you may implement (return `InvalidArgument`) only if you test them.
- `Engine` stub: `prepare` validates the configuration against SPEC (fs > 0; sub-block S ∈ {16, 32} per SPEC-CONV; `maxBlock` ≥ 1; `channels` ≥ 1; `threads` ≥ 1) returning `InvalidArgument` on a violation, otherwise allocates what `process` needs and returns `Status::NotImplemented`. `process` writes exact zeros (`0.0f`) to `frames` samples of every output channel, reads and ignores events, and never allocates, locks, throws or calls the system — even when `prepare` was never called or failed (then it still zeroes whatever `AudioOut` it is given). `reset` does nothing; `setInstrument` accepts and releases its argument (document that the stub never swaps); `popDiagnostic` returns `false`.

**P0.4-R4 — parameter registry.**

- `params.hpp`: `using ParamId = std::uint32_t;`, `enum class ParamClass { Continuous, Structural };`, a `ParamInfo` struct (id, name, unit, min, max, default, class, SPEC key, short description; string fields as `std::string_view` to static storage), and `[[nodiscard]] std::span<const ParamInfo> paramRegistry() noexcept;` plus `[[nodiscard]] const ParamInfo* findParam(ParamId) noexcept;` (both real-time safe: no allocation; lookup by binary search or a static table).
- Contents of v1: (a) every **continuous** parameter SPEC-API's "Parameter classes" lists — sustain, sostenuto and soft pedal values, una corda shift, sympathetic gain κ_s, output gains, damper timing — one entry per independent quantity; (b) the instrument-wide **structural** parameters whose defaults SPEC-INST's piano table gives (for example longitudinal transmission κ_L, longitudinal modes M_L, local bridge modes M_b, sympathetic low-pass f_symp, string f_max). Per-key and per-segment physical parameters stay in the description structs, not in the registry; say so in docs/dev/interfaces.md.
- Units: SI symbols; dimensionless quantities use `"1"`; never empty. Ranges and defaults from SPEC where SPEC gives them (cite the row); where SPEC gives none, choose a range, mark it `provisional` in the description and docs/dev/interfaces.md, and list each in the report for the planner. Gains: state whether linear or dB.
- IDs: stable 32-bit numbers, never reused or renumbered; document the allocation scheme (for example blocks of 1000 per area) in docs/dev/interfaces.md.
- `params.json` at the repository root, **generated**: `tools/params/` holds a small C++ executable `pme_params_json` (links `pme::engine`) that writes the registry as JSON (`schema_version: 1`, `interfaces_version: 1`, one object per parameter with every `ParamInfo` field), deterministic (sorted by ID, fixed number formatting). The committed `params.json` is that output; a test fails when they differ.

**P0.4-R5 — events.** In `events.hpp`: one struct per row of the SPEC-API events table with exactly its fields — `NoteOn` (key, velocity ν), `NoteOff` (key, release velocity), `KeyDepth` (key, depth), `Pedal` (which: `Sustain` / `Sostenuto` / `Soft`, value 0–1), `Pluck` (segment, position, force, angle, kind), `Bend` (segment, cents), `Param` (id, value) — each documented with units and ranges from SPEC; `Event` = sample offset (`std::int32_t`, within the host block, ≥ 0) plus a `std::variant` of the seven (or a tagged union); `EventList` = `std::span<const Event>`, sorted by offset (documented precondition of `process`). Event types must be trivially copyable so they can cross the lock-free SPSC queues (Real-time rule 3); add `static_assert`s in a test.

### How each test is built

All in `engine/tests/interfaces/` (your own doctest `main.cpp` and `add_test`, per the shared conventions).

**P0.4-T1.** At configure time, glob `engine/include/pme/*.hpp` and generate one translation unit per header that includes it twice (proves include guards or `#pragma once`) and nothing else; compile them all into the test executable with the project warning flags and warnings as errors. A `TEST_CASE("P0.4-T1 every public header compiles on its own")` checks that the number of generated translation units equals the number of headers (so a header added later is checked automatically). The CI matrix (MSVC, clang-cl, AppleClang, GCC, Clang) is "all compilers"; locally build with GCC and Clang. Label `unit`.

**P0.4-T2.** `TEST_CASE("P0.4-T2 stub Engine processes silence in the rt-safety build without allocating")`, label `unit;rt`, registered **only when `PME_RTSAFETY` is ON and `TARGET pme_rtcheck` exists** (otherwise print a CMake `STATUS` message saying it is skipped until P0.2 is merged). It prepares an `Engine` (non-audio), fills the output buffers with a non-zero pattern, then inside `pme::rtcheck::ScopedRealtimeThread` calls `process` for at least 100 blocks of varied sizes (1, 16, 32, 64, 128, `maxBlock`) with a mixed event list (each of the seven event types), calls `reset` and `popDiagnostic`, and asserts every output sample is exactly `0.0f`. Any allocation aborts the process through rtcheck and fails the test. Also in this executable, for every preset: `P0.4-R3 …` cases that (a) count allocations with a test-local replacement of global `operator new` — compiled **only when `PME_RTSAFETY` is OFF**, so it never collides with rtcheck's replacement — and assert zero allocations across the same `process` calls; (b) check every compile-function stub returns `Status::NotImplemented` and leaves its out-parameter unchanged; (c) check `prepare` returns `InvalidArgument` for each invalid configuration field and `NotImplemented` for a valid one; (d) call `toString` on every `Status`; (e) `static_assert` that event types are trivially copyable and that `process`, `reset`, `popDiagnostic`, `setInstrument` are `noexcept`.

**P0.4-T3.** `TEST_CASE("P0.4-T3 parameter IDs are unique, units non-empty, ranges valid")`, label `unit`: IDs unique; names unique and non-empty; units non-empty; `min < max`, `min ≤ default ≤ max`, all finite; class is one of the two; `findParam` finds every entry and returns null for an unused ID. A second CTest test (label `unit`, name beginning `P0.4-R4`) runs `pme_params_json` into the build directory and compares it with the committed `params.json` (`cmake -E compare_files`), failing on any difference.
