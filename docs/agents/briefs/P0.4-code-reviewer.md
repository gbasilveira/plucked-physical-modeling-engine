## Review checklist for P0.4

**Scope and process**

1. P0.4 commits touch only P0.4's paths, the "Engine modules" section of the root `CMakeLists.txt` plus one block appended at the end (`# ---- P0.4: … ----` / `# ---- end P0.4 ----`), and the "Targets" section of docs/dev/build.md. Messages start `P0.4: `. No tag was created.

**Headers (R1, R2, ADR-0006)**

2. Thirteen R2 headers exist, plus at most `status.hpp`, `types.hpp`, `version.hpp` and an umbrella `pme.hpp`. Each SPEC-API name is declared exactly once, in the header the brief's map gives (`grep` every identifier of the SPEC-API code blocks and the events table).
3. Every SPEC-API struct has exactly SPEC's fields, names, types and order; deviations are listed in docs/dev/interfaces.md with a reason. Members of types SPEC-API leaves open are either cited to a SPEC section or marked provisional and listed in the report's `spec_issues`. Spot-check `OscCoeffs` against SPEC-OSC's Contract (β, κ, γ float32; ω̂², σ̂ float64).
4. Signatures follow ADR-0006: non-real-time failing functions return `[[nodiscard]] Status` with the SPEC return type as a final reference out-parameter; `Engine::prepare` returns `[[nodiscard]] Status`; `setInstrument`, `process`, `reset`, `popDiagnostic` keep SPEC's parameters and are `noexcept`. `Status` has exactly `Ok`, `NotImplemented`, `InvalidArgument`, `Rejected`.
5. Every declaration's comment names its SPEC key, its thread and its failure statuses. Headers contain no function bodies except `= default`/`= delete` (search for `{` after a `)` outside struct and enum definitions), only standard-library includes, and `CompiledInstrument` is opaque.

**Stubs (R3, T2)**

6. Placeholders deleted in exactly `osc`, `string`, `bridge`, `body`, `runtime`; kept unchanged in the other six modules. Every compile-function stub returns `NotImplemented` and leaves its out-parameter unchanged.
7. `Engine::process` stub: zeroes `frames` samples on every channel, ignores events, contains no allocation, lock, exception, I/O or system call (read it); works without a successful `prepare`. `prepare` validates fs, S ∈ {16, 32}, `maxBlock`, `channels`, `threads`.
8. On the merged branch, `linux-rt-safety` with GCC and with Clang: the P0.4-T2 test is registered and passes. Negative check in scratch: add `std::vector<float> v(1);` inside the stub `process`; T2 must abort and fail. On `linux-debug`, the allocation-counting `P0.4-R3` case passes and fails with the same injected allocation.
9. Every stub function is called by a test: run the `linux-coverage` preset and P0.2's coverage script (or gcovr) on `engine/src/` minus `*_placeholder.cpp`; line coverage ≥ 90%.

**Registry (R4, T3)**

10. Registry contains every continuous parameter SPEC-API lists and the instrument-wide structural ones from SPEC-INST's piano defaults; ranges and defaults cite SPEC or are marked provisional; units SI, `"1"` for dimensionless; ID scheme documented. `paramRegistry` and `findParam` are `noexcept` and do not allocate.
11. T3 test passes; in scratch, duplicate an ID, empty a unit, swap a min and max — each fails. `params.json` equals `pme_params_json` output (the `P0.4-R4` test), is deterministic (run twice, byte-identical), and is valid JSON.

**Events (R5)**

12. Seven event structs with exactly the SPEC-API table's fields; units and ranges documented; `Event` carries a non-negative `std::int32_t` sample offset; `EventList` is a span with the sorted-by-offset precondition documented; trivially-copyable `static_assert`s exist.

**Build and T1**

13. `cmake --build --preset linux-debug --target pme_engine` builds all eleven modules (carried follow-up); docs/dev/interfaces.md and the build.md "Targets" section describe it.
14. T1: one generated translation unit per header, each including it twice; the count check passes; adding a scratch header `engine/include/pme/scratch.hpp` with an error makes the build fail. Build with GCC and Clang locally; with the orchestrator's CI link, all matrix compilers.
15. `clang-format --dry-run --Werror` and `clang-tidy -p build/linux-debug` pass on all P0.4 C++; `check_spdx.py` passes.

**Policy (R6)**

16. docs/dev/interfaces.md quotes the card's compatibility policy, defines breaking changes, points to docs/icr/README.md; `version.hpp` states major version 1.
