## Requirements

1. P0.5-R1 Stiff damped string with an energy-conserving finite-difference scheme and configurable grid.
2. P0.5-R2 Hammer contact with an iterative (Newton) energy-conserving scheme, deliberately different from the engine's SAV method.
3. P0.5-R3 Bridge as a lumped mass–spring–dashpot or a conductance, shared by several strings, with both polarisations.
4. P0.5-R4 Finite-difference orthotropic Kirchhoff plate on a rectangle, coupled to strings at bridge points.
5. P0.5-R5 Distributed string–barrier collision (penalty potential, Newton solve).
6. P0.5-R6 Tension modulation and longitudinal waves (iterative scheme).
7. P0.5-R7 Grid-refinement and energy-monitor tools; Python bindings and a CLI that render scenarios to features and WAV.

## Tests that must pass

- **P0.5-T1** string frequencies converge at the scheme's order to the analytic stiff-string values;
- **P0.5-T2** lossless energy is conserved to 10⁻¹² relative per step;
- **P0.5-T3** hammer–wall contact time matches the analytic value within 0.1% on a fine grid;
- **P0.5-T4** simply supported rectangular plate modes match the analytic orthotropic values within 0.1%.

## Review checklist for P0.5

**Scope, process and independence**

1. P0.5 commits touch only P0.5's paths in the ownership table: `reference/**`, `tools/reference-cli/**`, `tools/tests/test_p0_5_*.py`, docs/dev/reference-solver.md, `pyproject.toml`, `uv.lock`, one root `CMakeLists.txt` block, one pr.yml block at the end, appended entries in `required_checks.json` and CONTRIBUTING.md, one docs/dev/ci.md subsection. Not `cmake/dependencies.cmake` (D1's). `uv run pytest tools/tests/test_p0_2_r7.py` passes.
2. Independence: no `#include` of anything under `engine/src/`; no link to `pme_engine` or any `pme_<module>` (inspect `cmake --build … --target help` / the link lines, and `grep -rn 'engine/src\|pme_osc\|pme_string\|pme_engine' reference tools/reference-cli`). In scratch, add a link to `pme_osc` from a reference target: configure must fail with the isolation message.
3. No modal synthesis, SPEC-OSC coefficients or SAV anywhere in the reference: the string, plate and contacts are physical-space finite differences with Newton iterations for nonlinear terms. Every scheme cites its SPEC section and its literature source.

**Physics (rerun and record numbers)**

4. R1: wound-string ρA, EI and tension-for-pitch re-implemented from SPEC-STR; the loss mapping σ₀ = b₁, σ₁ = b₃T/ρA, σ₃ = b₃EI/ρA reproduces σ(ω) = b₁ + b₃ω² for a lossy string within 1% on a fine grid (measure with `pme_analysis`); b₂ ≠ 0 is rejected with a clear error.
5. T1: rerun; record the observed orders for both B values and five partials; the error decreases monotonically. Independent check: a third string (B ≈ 10⁻³, L = 0.5 m, clamped ends if supported, else pinned) converges at the same order.
6. T2: rerun every case; record worst per-step drift. Check that the energy expression is the scheme's discrete energy (a quantity that is exactly conserved), not a continuous approximation.
7. T3: rerun at two K values; compute t\_c yourself from SPEC-HAM's formula (Gamma functions) and compare; rebound speed. Check the Newton loop has a convergence test and reports failure.
8. T4: rerun; compute the analytic ω\_mn yourself; check the ten lowest modes are matched to the right (m, n) (no missed or doubled modes) and within 0.1%.
9. R3: the conductance cross-check (ORC-06 formula) within 1%; both polarisations present; several strings share one bridge point; energy balance with the lumped bridge.
10. R4 coupling: string-to-plate spreading and interpolation are adjoint (energy-neutral): total energy of a lossless string + plate system is conserved to the T2 bound.
11. R5 and R6: energy tests at their stated bounds; R6 small-amplitude frequencies within 0.1% of SPEC-GEO's linear values.

**Tools and CI (R7)**

12. Scenario JSON Schema exists and validates the example scenarios; the CLI `render` writes features that `pme_golden_compare` reads, a WAV `pme_analysis` reads, and an energy trace; `refine` prints orders.
13. Python module builds with `-DPME_BUILD_PYTHON_BINDINGS=ON`; the Python test's features equal the CLI's for the same scenario; the `reference-python` job sets `PME_REFERENCE_PYDIR` and fails on a skip; JUnit uploaded as `junit-reference-python-<system>`.
14. Heavy cases are registered only for optimised builds and still run in CI on all three systems (rt-safety presets, macos-universal); each debug-build case runs in under 60 s (time them).

**Quality**

15. `clang-format --dry-run --Werror` and `clang-tidy -p build/linux-debug` clean; `ruff`, `mypy` (strict), `check_spdx.py`, `pytest` pass; ctest passes in `linux-debug` and `linux-rt-safety` with GCC and Clang; docs/dev/reference-solver.md and reference/README.md cover schemes, orders, limits and usage.
