### Shared conventions (identical in the P0.2, P0.3 and P0.4 briefs)

- **Test names.** Every doctest `TEST_CASE` name begins with a requirement, test or oracle ID, a space, then a description: `P0.2-T1 allocation inside ScopedRealtimeThread aborts`. The ID matches `^((P0\.[1-5]|[ABCPDEVH][0-9]+)-[RT][0-9]+|ORC-[0-9]{2}) `. Python tests are named `test_<id>_<what>` with the ID lower-cased and `.`/`-` replaced by `_` (`test_p0_2_t2_misformatted_file_fails`), and their docstrings begin with the ID.
- **CTest labels.** Every registered CTest test carries at least one of: `unit`, `oracle`, `integration`, `golden`, `rt`, `perf`, `fuzz`, `soak`. `rt` marks tests that must also pass under the `rt-safety` preset. The pull-request workflow runs `ctest -LE "perf|fuzz|soak"`; the nightly workflow runs the `perf`, `fuzz` and `soak` labels in their jobs.

Until it is merged, P0.2 and P0.4 build their doctest executables directly: link `doctest::doctest` and `pme_build_options`, provide their own `main.cpp` with `DOCTEST_CONFIG_IMPLEMENT_WITH_MAIN`, register them with `add_test`, set `LABELS`, and set `COMPILE_WARNING_AS_ERROR ON`. The orchestrator may later move them onto the helper.
- **rtcheck API** (you implement it; P0.4 codes against it):

  ```cpp
  // engine/src/rtcheck/include/pme/rtcheck/rtcheck.hpp   (target pme_rtcheck, alias pme::rtcheck)
  namespace pme::rtcheck {
  // Marks the current thread real-time for the object's lifetime. Nestable.
  // In the rt-safety build (PME_RTSAFETY=1) any allocation or blocking call on a marked
  // thread prints a diagnostic to stderr and calls std::abort(). Otherwise a no-op.
  class ScopedRealtimeThread {
  public:
      ScopedRealtimeThread() noexcept;
      ~ScopedRealtimeThread();
      ScopedRealtimeThread(const ScopedRealtimeThread&) = delete;
      ScopedRealtimeThread& operator=(const ScopedRealtimeThread&) = delete;
  };
  [[nodiscard]] bool isRealtimeThread() noexcept;   // true inside a scope on this thread
  [[nodiscard]] constexpr bool enabled() noexcept;  // true in the rt-safety build
  // Called by the project's own blocking primitives (later phases) before they block.
  void blockingCall(const char* what) noexcept;
  }  // namespace pme::rtcheck
  ```

### How each test is built

**P0.2-T1.** In `engine/tests/rtcheck/`, a doctest executable (label `unit;rt`) registered only when `PME_RTSAFETY` is ON. doctest has no death tests: the test case `P0.2-T1 allocation inside ScopedRealtimeThread aborts` re-launches its own executable as a child process with an argument that makes the child enter a `ScopedRealtimeThread` and call `new int`, then asserts that the child terminated abnormally (signal `SIGABRT` on POSIX; exit code 3 or the abort status on Windows) **and** that its stderr contains the rtcheck diagnostic. Include the controls in the same executable, each its own test case named with `P0.2-R5`: allocation outside a scope does not abort; allocation after the scope ends does not abort; a nested scope still traps; `pthread_mutex_lock` (Linux, macOS) and `blockingCall()` (all systems) inside a scope abort. Use `posix_spawn`/`waitpid` on POSIX and `CreateProcessW`/`WaitForSingleObject` on Windows; no shell. The test must run and pass in the `rt-safety` preset of every pull-request matrix entry.
