### Shared conventions (identical in the P0.2, P0.3 and P0.4 briefs)

- **Test names.** Every doctest `TEST_CASE` name begins with a requirement, test or oracle ID, a space, then a description: `P0.2-T1 allocation inside ScopedRealtimeThread aborts`. The ID matches `^((P0\.[1-5]|[ABCPDEVH][0-9]+)-[RT][0-9]+|ORC-[0-9]{2}) `. Python tests are named `test_<id>_<what>` with the ID lower-cased and `.`/`-` replaced by `_` (`test_p0_2_t2_misformatted_file_fails`), and their docstrings begin with the ID.
- **CTest labels.** Every registered CTest test carries at least one of: `unit`, `oracle`, `integration`, `golden`, `rt`, `perf`, `fuzz`, `soak`. `rt` marks tests that must also pass under the `rt-safety` preset. The pull-request workflow runs `ctest -LE "perf|fuzz|soak"`; the nightly workflow runs the `perf`, `fuzz` and `soak` labels in their jobs.

Until it is merged, P0.2 and P0.4 build their doctest executables directly: link `doctest::doctest` and `pme_build_options`, provide their own `main.cpp` with `DOCTEST_CONFIG_IMPLEMENT_WITH_MAIN`, register them with `add_test`, set `LABELS`, and set `COMPILE_WARNING_AS_ERROR ON`. **P0.3-R3 — analysis library.**

- C++: static library `pme_analysis` (alias `pme::analysis`) in `tools/analysis/`, headers under `tools/analysis/include/pme/analysis/`, namespace `pme::analysis`, float64 throughout, no engine headers. Python mirror: package `pme_analysis` in `tools/analysis/pme_analysis/` (NumPy/SciPy only), same function set and same results within the T1 tolerances. Add `tools/analysis` to pytest `pythonpath` and mypy `mypy_path` in `pyproject.toml`; regenerate `uv.lock` only if dependencies change (they should not).
- Functions (names are yours; document each in docs/dev/analysis.md with its method and the SPEC-ORC row or PLAN-VAL line it serves):
  - **Partial tracking:** given a signal, sample rate and either a list of approximate frequencies or a peak-picking rule, return per partial its frequency, its amplitude envelope over time (frame times and amplitudes), and its phase at t = 0. Required accuracy is set by P0.3-T1: 0.01 cent is about 6 × 10⁻⁶ relative, beyond FFT-bin interpolation; use a parametric fit (for example, FFT peak estimates refined by nonlinear least squares on complex damped exponentials, or a subspace method such as ESPRIT or matrix pencil). Partials 1 Hz apart must be separated (piano unisons, ORC-07).
  - **Decay rate and T60:** σ in s⁻¹ for a partial (amplitude ∝ e^(−σt)), T60 = 3 ln 10 / σ; and a two-slope (double-decay) fit returning both rates and the knee time.
  - **Inharmonicity:** least-squares fit of f₀ and B to measured partials f_n = n f₀ √(1 + B n²) (SPEC-STR), returning both and the residual in cents.
  - **Contact time:** from a sampled contact-force signal, the interval where force exceeds a threshold, with sub-sample interpolation of both crossings (ORC-08's "max(1%, 1 sample)" needs better than one sample).
  - **Spectral envelope:** smoothed magnitude spectrum on a fixed log-frequency grid (state the smoothing: for example fractional-octave or cepstral), in dB.
  - **Energy accounting:** from a per-step energy series (float64), the maximum relative drift `max|Hⁿ − H⁰|/|H⁰|`, the maximum relative per-step change, and a check for "non-increasing within tolerance" (ORC-02, ORC-09, ORC-15 use these forms).
- FFT and linear algebra: no new third-party dependency beyond ADR-0005's JSON library. Write the FFT you need (radix-2 plus Bluestein, or mixed radix) and small dense solves in the library, each with its own unit test against a direct implementation (DFT, explicit solve). If you conclude a library is unavoidable, stop that item and report it; the planner writes the ADR.

**P0.3-R4 — golden features.**

- Format: JSON, described by a JSON Schema (draft 2020-12) at `tools/analysis/golden-features.schema.json`, with `schema_version: 1`; fields at least: scenario name, sample rate, producer (tool and version), partials (index, frequency Hz, amplitude, σ s⁻¹, T60 s, optional second decay), spectral envelope (grid and dB values), optional contact time and energy-drift values, and `tolerances`: a default per feature kind plus optional per-partial overrides. Units in field names or a `units` block; SI units (Numerics rule 6).
- Default tolerances: frequency 0.01 cent (ORC-01, ORC-16), decay rate 0.5% relative (ORC-16), spectral envelope 1 dB (ORC-17), contact time 1% relative (ORC-08); amplitude 0.1 dB (the planner's choice; no SPEC-ORC row sets it). Document them; golden files may override.
- C++ comparator in `pme_analysis` (reads both files with nlohmann/json, returns per-feature pass/fail with the measured difference and the tolerance, and an overall verdict) plus a CLI `pme_golden_compare <reference.json> <candidate.json>` with exit 0 / 1 and a readable diff. Python mirror: reader, writer and comparator in `pme_analysis` with the same verdicts.

**P0.3-R6 — benchmark harness.**
