Run each check; record the command and result.

**Scope and process**

1. P0.2 commits touch only paths the implementer brief's ownership table gives P0.2, plus one block appended at the end of the root `CMakeLists.txt` delimited by `# ---- P0.2: … ----` / `# ---- end P0.2 ----` and nothing else in that file. 2. `.github/workflows/bootstrap-build.yml` is deleted (follow-up 1).

**Workflows (R1–R3, R6)**

3. Every workflow: top-level `permissions: contents: read`; any wider per-job permission has a comment and a reason; no `secrets.` reference; every `uses:` is a 40-hex SHA with a tag comment; explicit runner images; tool versions exact. Run `actionlint` (pinned) over all three files if you can obtain it; otherwise read them line by line.
4. `pr.yml` matrix has exactly the six entries and presets of the brief's R1 table (MSVC, clang-cl, macOS arm64, macOS universal with `lipo -archs` check, Linux GCC, Linux Clang with the Clang runtime installed), plus `lint`, `python` (three systems), `coverage` and `deps`. `ctest` uses `-LE "perf|fuzz|soak"` and `--output-junit`; no test names are hard-coded.
5. `nightly.yml`: schedule, `workflow_dispatch`, self-push trigger; `sanitizers` covers linux-asan and linux-tsan with GCC and Clang, macos-asan, macos-tsan, windows-asan, and **no** Windows TSan (ADR-0004); `performance`, `fuzz`, `soak` exist and pass with no tests (`--no-tests=ignore` only there). TSan ASLR handling (follow-up 6) is present or documented as unnecessary with evidence.
6. `release.yml`: tag pattern `v[0-9]+.[0-9]+.[0-9]+*`; builds and tests `release` on the three systems; uploads artifacts; no publishing step, no `contents: write`, no `gh release`, no registry push; version check against `project(VERSION …)`; dry-run mode on self-push.
7. JUnit files uploaded with `if: always()`; retention 14 / 30 / 90 days for PR / nightly / release; coverage job produces HTML and Cobertura with a pinned gcovr, enforces ≥ 90% on `engine/src/` minus `rtcheck/`, platform glue and `*_placeholder.cpp`, and passes with "no engine sources measured" when the set is empty. **Lint (R4)**

**RT-safety trap (R5, T1)**

11. API matches the brief exactly (header path, namespace `pme::rtcheck`, the four declarations); `pme_rtcheck` is not linked into `pme_engine`.
12. In the `rt-safety` preset on Linux (GCC and Clang): the T1 executable passes; read the test to confirm it checks abnormal termination **and** the diagnostic text, and that the controls (outside scope, after scope, nested scope, mutex lock, `blockingCall`) exist. 15. Setting `PME_RTSAFETY=ON` together with `PME_SANITIZER=asan` fails at configure time.
16. docs/dev/rtcheck.md lists, per system, what is intercepted and what is not; anything not intercepted is also in the handoff report's `open_risks`.
