## Review checklist for B1

**Scope and process**

1. B1 commits touch only the B1 rows of the ownership table, the root `CMakeLists.txt` block `# ---- B1: … ----`, and — in one separate commit `B1: jsonschema dependency` — exactly two added lines in pyproject.toml plus a `uv lock`-generated uv.lock. `git diff <base> -- engine/include cmake/dependencies.cmake .github` is empty. Messages start `B1: `.

**B1-R1 schema mirrors the structs**

2. Walk every struct in the eight headers member by member against its `$defs` entry: same name, same order, same JSON type (int vs number vs string enum vs array), same default for members with a default initialiser (and optional in the schema exactly when the header has a default or `std::optional`). Report every mismatch. Check the `ExciterParams` one-key encoding covers all five alternatives.
3. Every numeric property has `x-unit` matching the header comment (spot-check at least 30, including `b2` = s^(-1/2), `HammerParams::K` = N/m^p, `rimStiffness` = N/m², `conductanceH` = s/kg, `unisonDetuneCents` = cent, angles = rad). Constraints are physical and sourced; flag any invented "typical" bound.
4. Cross-field rules (unique keys, bridge-point indices, dOuter ≥ dCore, grid size, barrier array lengths, hash resolution, At0-after-AtL as one separately named check) exist in **both** loaders.

**B1-R2 versions**

5. Version 0 matches interfaces-v1 (2daee85) for the listed structs (`git show 2daee85:engine/include/pme/exciters.hpp`, `body.hpp`, `instrument.hpp`); the migration table is implemented identically in Python and C++; plectrum and finger v0 fail with `migration`; future versions fail with `version`; writers always write the current version.

**B1-R3 manifest**

6. SHA-256 (C++) passes the FIPS 180-4 vectors; offsets, sizes, alignment and overlap are checked; paths reject `..` and absolute paths; `verifyBlobs` defaults as briefed.

**B1-R4 loaders**

7. `pme_loader` is a separate static library, links nlohmann/json, is not reachable from `pme_engine` or any `pme_<module>` (configure a scratch build where you add it to `pme_runtime`'s link and confirm the P0.3 isolation check fires, then revert); `pme_runtime`'s glob does not include `loader/`. No exception escapes the API; `out` unchanged on failure (ADR-0006).
8. Python models are frozen dataclasses with the same fields and defaults as the structs; mypy strict and ruff clean.
9. Canonical form: run both writers on every committed file and on a randomised instrument you generate in scratch (random values including subnormal-free extremes like 1e-300, 1e300, 0.1, 1/3, negative zero where allowed): outputs byte-identical across languages and stable under write → read → write.

**B1-R5 errors**

10. JSON Pointer paths are exact (escape `~` and `/` per RFC 6901 — add a fixture with a key needing escape if names allow it, or check unknown-key reporting of such a key); codes from the closed list; both languages report the same (path, code) sets on every malformed fixture; all errors reported, capped at 100.

**B1-R6 examples**

11. Regenerate generic-grand-88 and test-guitar-6: byte-identical. Independently recompute, for keys 21, 40, 41, 60, 69, 108, the speaking length, diameters and closed-form tension (SPEC-STR) from the brief's anchors and compare with the file. Tensions in 400–2000 N. Keys 21–108, 1/2/3 strings per range, dampers on 21–88 only. The nominal status is documented.
12. test-monochord and test-unison-pair match the brief's values (key 45 and 60, b₂ = 0, rectangle plate without outline, grid, ribs or bridges).

**Tests and quality**

13. B1-T1, B1-T2, B1-T3 are built as briefed (split round trip at committed files, both halves on all three systems; `all-fields.json` covers every member, enum value and exciter alternative). Rerun them.
14. `clang-format --dry-run --Werror`, `clang-tidy -p build/linux-debug`, `ruff check`, `ruff format --check`, `mypy` clean; `ctest --preset linux-debug` (GCC and Clang) and `uv run pytest compiler/tests` pass; `test_p0_3_r1` (test names) passes; coverage of `engine/src/runtime/loader` keeps engine/src at or above 90%.
15. docs/dev/instrument-format.md covers what the implementer brief's Definition of done lists.
