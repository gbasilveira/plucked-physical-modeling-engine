### How to meet each requirement

**P0.1-R1 — layout and targets.**

- Create every directory of the Software guidelines layout. A directory with no P0.1 content gets an empty `.gitkeep`.
- Engine modules and targets, one static library each, built from `engine/src/<module>/`:

  | Directory | Target |
  | --- | --- |
  | engine/src/osc/ | pme\_osc |
  | engine/src/string/ | pme\_string |
  | engine/src/bridge/ | pme\_bridge |
  | engine/src/body/ | pme\_body |
  | engine/src/nonlinear/ | pme\_nonlinear |
  | engine/src/exciters/ | pme\_exciters |
  | engine/src/dampers/ | pme\_dampers |
  | engine/src/barriers/ | pme\_barriers |
  | engine/src/runtime/ | pme\_runtime |
  | engine/src/sched/ | pme\_sched |
  | engine/src/simd/ | pme\_simd |

  `pme_engine` is the aggregate target that links all eleven. Also provide `pme::` aliases (`pme::osc`, … , `pme::engine`). Do not create `engine/src/rtcheck/` or `pme_rtcheck`; that is P0.2.
- **Placeholders only, no engine behaviour.** Each module gets exactly one source, `engine/src/<module>/<module>_placeholder.cpp`, with an SPDX header, a comment saying it is replaced in P0.4 (stubs) and the module's own phase, and one trivial function so that every static library has a symbol (an empty object makes MSVC's librarian warn). For example:

  ```cpp
  // SPDX-License-Identifier: MIT
  // Placeholder so that pme_osc is a buildable library target (P0.1-R1).
  // Replaced by stub sources in P0.4 and by the modal oscillator in A1.
  namespace pme::detail {
  int placeholder_osc() noexcept;
  int placeholder_osc() noexcept { return 0; }
  }  // namespace pme::detail
  ```

  `engine/include/pme/` holds only `.gitkeep`; P0.4 owns every public header. `engine/tests/` holds only `.gitkeep`; P0.3 owns doctest integration. No CMake targets for `reference/`, `plugin/`, `bindings/` in P0.1.
- `pme_simd` links Highway privately (ADR-0001), so every preset proves Highway builds with the project's flags. No other module links Highway.

**P0.1-R2 — presets.**

- `CMakePresets.json` (schema version 6, `cmake_minimum_required(VERSION 3.25)`), Ninja generator everywhere, binary directory `build/<preset>`.
- Configure presets named `<system>-<config>` with system ∈ {`linux`, `macos`, `windows`} and config ∈ {`debug`, `release`, `rt-safety`, `asan`, `tsan`, `coverage`}, each gated by a `condition` on `${hostSystemName}` (`Linux`, `Darwin`, `Windows`). Per ADR-0004 (Proposed), **there is no `windows-tsan`**: 17 presets in total. Do not create a Windows preset named tsan that builds without the sanitizer. Use hidden base presets to avoid repetition. Add one build preset and one test preset per configure preset, same name.
- Meaning of each configuration:

  | Config | Build type | Extra |
  | --- | --- | --- |
  | debug | Debug | — |
  | release | Release | — |
  | rt-safety | RelWithDebInfo | cache option `PME_RTSAFETY=ON`, which defines `PME_RTSAFETY=1` on project targets. The trap library itself is P0.2-R5; in P0.1 the option only exists. |
  | asan | Debug | GCC/Clang/AppleClang: `-fsanitize=address,undefined -fno-omit-frame-pointer`; MSVC: `/fsanitize=address` (drop `/RTC1`, keep `/Zi`, no incremental linking) |
  | tsan | Debug | `-fsanitize=thread` (Linux and macOS only) |
  | coverage | Debug | GCC: `--coverage`; Clang/AppleClang: `-fprofile-instr-generate -fcoverage-mapping`; Windows: MSVC Debug with full PDBs (`/Zi`, `/DEBUG:FULL`) for an external coverage tool in P0.2. clang-cl source-based coverage is an allowed alternative if it builds cleanly; record the choice in docs/dev/build.md. |

- Compilers: Linux and macOS presets do not hard-code a compiler (CI and developers choose with `CC`/`CXX`; P0.2 runs Linux with both GCC and Clang). Windows presets use MSVC `cl` with Ninja from a Visual Studio developer shell; they must also work when `CC`/`CXX` select `clang-cl` (P0.2 adds that matrix entry), except where a preset explicitly needs one compiler.
- Project-wide compile settings, applied to **project targets only** (through an interface target such as `pme_build_options`), never to third-party targets:
  - C++20, extensions off.
  - Warnings: GCC/Clang `-Wall -Wextra -Wpedantic -Wshadow -Wconversion`; MSVC `/W4 /permissive- /Zc:__cplusplus /utf-8`.
  - Warnings as errors: target property `COMPILE_WARNING_AS_ERROR ON` on project targets (do not set `CMAKE_COMPILE_WARNING_AS_ERROR` globally — third-party code must not fail our build). Add third-party include directories as `SYSTEM`.
  - Floating point (Numerics rule 2): never `-ffast-math`, `-Ofast`, `-funsafe-math-optimizations` or `/fp:fast`. Fix FMA contraction explicitly per build: `-ffp-contract=off` on GCC/Clang/AppleClang, `/fp:precise` on MSVC. Write the chosen flags in docs/dev/build.md.
- macOS presets build the native architecture; the universal build is P0.2's.

**P0.1-R3 — Python.**

Leave that dependency's pin as an explicit `message(FATAL_ERROR ...)` guarded by `PME_FETCH_ALL_DEPS` (or omit it), mark P0.1-R4 `not met`, and list each unreachable dependency with the exact command and error under `open_risks`. Leave a comment in `dependencies.cmake` for D1/D2: pass our pinned CLAP and VST 3 SDK source directories to clap-wrapper instead of letting it download them; the AudioUnit SDK pin is added by D2.

### How P0.1-T1 is evidenced (decided for this phase)

The card requires three-system evidence, but the pull-request workflow is P0.2's output (`.github/workflows/pr.yml`). P0.1 therefore ships one **temporary, build-only** workflow, `.github/workflows/bootstrap-build.yml`, which P0.2 deletes when `pr.yml` lands:

- Triggers: `push`, `pull_request`, `workflow_dispatch`; `permissions: contents: read`; a `concurrency` group that cancels superseded runs.
- Job `presets`: matrix over the 17 presets on `ubuntu-latest` (GCC), `macos-latest` (arm64, AppleClang) and `windows-latest` (MSVC via a Visual Studio developer-shell action); each runs `cmake --preset <p>` then `cmake --build --preset <p>`. Cache `CPM_SOURCE_CACHE`.
- Job `deps`: `ubuntu-latest`, configures `linux-release` with `-DPME_FETCH_ALL_DEPS=ON` (proves every pin resolves).
- Job `python`: on all three systems: install uv, `uv sync --locked --all-extras`, `uv run pytest`, `uv run ruff check`, `uv run ruff format --check`, `uv run mypy`, `uv run python tools/check_spdx.py`.
- Every action is referenced by full commit SHA with the tag in a comment (ADR-0003). No secrets, no publishing, no caches beyond CPM and uv.
- The workflow's `name:` says it is temporary and owned by P0.1, to be removed by P0.2.

Before committing, run locally on Linux: all six `linux-*` presets with GCC **and** with Clang (`CC=clang CXX=clang++`, separate build directories), the `PME_FETCH_ALL_DEPS=ON` configure, and the whole `python` job. Also prove warnings are errors: in a scratch copy (never committed), add an unused variable to one placeholder and show the build fails.

Reporting rule: a test is `pass` in the handoff report only with a `ci_run` link to a bootstrap-build run that is green on all three systems. Without such a link, report it `not run`, set `status` to `partial`, and put the local Linux evidence (commands, compilers, results) in `notes`. Never report `pass` from local runs alone.

### P0.1-T3

- `tools/check_spdx.py`: Python 3.12, standard library only, ruff- and mypy-strict clean, SPDX header itself. It lists tracked files with `git ls-files` (so build output is ignored), and fails (exit 1, listing each file) when a file that needs a header lacks `SPDX-License-Identifier: MIT` in its first five lines.
- Needs a header: C/C++ sources and headers, CMake files (`CMakeLists.txt`, `*.cmake`), Python, shell and PowerShell scripts, YAML, TOML, and comment-capable dotfiles (`.clang-format`, `.clang-tidy`, `.editorconfig`, `.gitattributes`, `.gitignore`, `CODEOWNERS`).

- Self-test `tools/tests/test_check_spdx.py`, test names beginning `test_p0_1_t3_`, docstrings beginning `P0.1-T3`: builds a temporary Git repository and shows the check passes on headed files and fails on a missing header, a wrong identifier and an unknown file type.
